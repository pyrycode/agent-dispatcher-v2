# #62 — `src/claude/spawn.ts` I/O wrapper around `claude -p --output-format stream-json`

Third file under `src/claude/`. Lands an async wrapper (`spawnClaude(args, env, opts?) → Promise<StreamParseResult>`) that spawns the Claude CLI, buffers stdout, and threads the buffer into `parseStream` (#9). The dispatcher's secret + coordination env (GitHub token, project board ids, Discord webhook, WIP counter, target repo path) is stripped on the way through. Consumer (not yet built): `src/loop/`.

## Surface

- `spawnClaude(args, env, opts?)` — runs the CLI, returns `StreamParseResult` unchanged from `parseStream`.
- `SPAWN_ENV_DENYLIST: ReadonlySet<string>` — seven entries, exported so a test pins exact contents.
- `scrubSpawnEnv(parentEnv) → NodeJS.ProcessEnv` — pure helper, exported separately so the policy can be reused without going through `spawnClaude`, and so tests can hit it directly.
- `ClaudeRunner = (cmd, args, env) => Promise<{ stdout, exitCode }>` — injectable subprocess runner. Default invokes `child_process.spawn`; tests substitute a mock.
- `SpawnClaudeOpts = { runner?, lastN? }` — `lastN` is forwarded verbatim to `parseStream`.

The default runner is intentionally **not** exported. Tests inject mocks; the loop ticket can either use the default (running through real `spawn`) or supply a richer runner (timeout, stdin pipe, log-tap) without renegotiating this wrapper's contract.

## Why these contracts

### Argv shape is the wrapper's job, not the caller's

`spawnClaude` prepends `-p --output-format stream-json` to the supplied `args`. Streaming-output policy is part of the wrapper's identity — callers express *what they want the CLI to do*; the wrapper owns *how the output arrives*. Passing those flags in `args` would double them; this is caller error, not validated by the wrapper.

### Denylist over allowlist for env scrub

`claude` reads a wide and shifting set of host vars (PATH, HOME, LANG, LC_*, TMPDIR, NODE_*, ANTHROPIC_*, …) — an allowlist would silently break on every new dependency. A seven-entry denylist keeps the leak surface bounded without reducing flexibility. The rationale is comment-pinned in `spawn.ts` so a future maintainer doesn't "tighten" to an allowlist and break propagation. Ported verbatim from v1's `agent-runtime.ts`; extending the list is explicitly a separate-commit operation so the exact-contents pin test (`SPAWN_ENV_DENYLIST — exact contents pin`) forces it through review.

### Wrapper threads bytes verbatim

`spawnClaude(stdoutBuffer)` is, by contract, equal to `parseStream(stdoutBuffer)`. The wrapper introduces no new transformation, no new return-shape widening, no swallowed exit-code state. The fixture-equivalence test (`returns parseStream(stdout) for the success fixture`) pins this — if a future maintainer wants to add `exitCode` or a raw-buffer field to the return shape, the test forces that to be an explicit, reviewed change.

### `exitCode` is read but not surfaced

`parseStream`'s `ExitReason` is what consumers route on. The result message carries `terminal_reason` (`max_turns`, `rate_limit`, …) and is authoritative even when the CLI exits 0. Surfacing the raw exit code today would add a field with no consumer; the lean shape wins. If a future ticket (e.g. safer-salvage's gate predicate) needs the exit code, widen to `{ result: StreamParseResult; exitCode: number }` then — until then, don't.

### Subprocess hygiene (default runner)

- **`shell: false` + argv array** — forecloses shell-quoting injection if a future caller threads user input through `args`. The wrapper's contract is "argv, no shell."
- **`stdio: ["ignore", "pipe", "pipe"]`** — no stdin today (no prompt to send). The loop ticket will widen `stdio[0]` to `"pipe"` to feed the prompt file. **Note for that ticket:** `child.stdin` is `null` unless `stdio[0] === "pipe"`.
- **stderr → parent's stderr unredacted** — claude's stderr is debug/progress noise that contains no env or token contents (v1-audited behaviour). Silencing it would hide CLI startup errors.
- **`child.on("error", reject)`** — `ENOENT` / `EACCES` reject the promise. The wrapper's caller decides retry vs. escalate.
- **`code ?? 0` on close** — signal-kill yields `null`; treating it as 0 is harmless *only because* `exitCode` is not currently surfaced (truncated stdout routes to `error` via `parseStream`). If `exitCode` is ever surfaced, change to `code ?? -1` and add a signal-kill fixture.

## Error policy

- **Runner rejects** (`ENOENT`, `EACCES`, …) → promise rejects unchanged. Caller's problem.
- **Non-zero exit + stdout present** → `parseStream` is still called. The stream is the source of truth: `subtype: "success"` plus exit 1 is treated as success, because that's a CLI contract violation the dispatcher can't usefully second-guess.
- **Empty / malformed stdout** → `parseStream` returns `exitReason: "error"`, `totalCostUsd: 0`, no session id. No throw introduced by this wrapper.

No new `try/catch` lives in `spawn.ts`. Policy is "propagate runner rejection; trust the parser otherwise."

## Patterns established by this ticket

- **I/O wrapper + pure parser composition under `src/claude/`.** The format-specific I/O surface (subprocess + buffer) lives in its own file alongside the format-specific pure parser (`stream.ts`); the wrapper returns the parser's struct unchanged. This is the template for any future Claude-CLI invocation: don't widen the parser return; don't reshape inside the wrapper. New CLI-output shape → new parser file; new invocation policy → new wrapper file.
- **Injectable runner for tests, default runner unexported.** The seam (`opts.runner`) exists so the test suite runs without `claude` on PATH and so future tickets can fault-inject timeouts / signals / log taps. Keep the default-runner private — exporting it would tempt future call sites to bypass the wrapper's argv + env-scrub contract.
- **Denylist exact-contents pin is the deterministic backstop for env-leak prevention.** The load-bearing test is `Array.from(SPAWN_ENV_DENYLIST).sort()` against a literal sorted array. Every new dispatcher secret must land in the denylist *and* the pinned array in the same commit. This is the "belt-and-suspenders" enforcement from `CLAUDE.md` — the agent-doc-comment instructs maintainers; the pin test catches them when they forget.
- **Argv shape is wrapper-owned, not caller-supplied.** `-p --output-format stream-json` lives in the wrapper. Callers passing those flags is caller error, not validated. The corollary: don't add caller-controlled toggles that change streaming-output policy — that's a contract change, not an option.

## Lessons learned

- **Don't pre-export the default runner just because you're exporting the type.** The temptation to ship `ClaudeRunner` type + `defaultClaudeRunner` value together is real, but every call site that bypasses `spawnClaude` to use the default directly also bypasses the env scrub. Keeping it unexported is the cheapest enforcement.
- **`exactOptionalPropertyTypes` means `key in result` ≠ `result[key] === undefined`.** The scrub tests use `expect("KEY" in result).toBe(false)` rather than `expect(result.KEY).toBeUndefined()` — strict absence is what the wrapper guarantees, and the looser assertion would silently pass an `out["KEY"] = undefined` regression.
- **Conditional opts-passing pattern matters under `exactOptionalPropertyTypes`.** `parseStream(stdout, opts?.lastN === undefined ? undefined : { lastN: opts.lastN })` — building `{ lastN: undefined }` and passing it would fail typecheck because the parser's `ParseStreamOpts.lastN` is `number | undefined` only at the property level, not at the parameter level. The branch reproduces the "either pass the option set, or pass `undefined`" shape that `exactOptionalPropertyTypes` demands.

## Out of scope (deferred to the loop ticket)

- **Timeout / SIGTERM lifecycle.** v1's `dispatch.ts` wires a `setTimeout` that kills the child after N minutes. The loop ticket owns subprocess lifecycle — adding it here would force a contract change when loop wires up.
- **stdin handling.** Today `stdio[0] === "ignore"`. The loop ticket pipes the prompt file in (v1 `dispatch.ts:273-279`); when it lands, widen to `"pipe"` and add a runner option for the stdin source.
- **`cwd` in the runner contract.** v1 passes `cwd: opts.cwd` (the worktree path). The loop ticket can widen `ClaudeRunner` to `(cmd, args, env, opts?: { cwd?: string }) => …` or inject a runner that closes over a worktree path. Architect's call.
- **Live logging of stream messages.** v1's `logStreamMessage` switch tees each parsed line to a log file. The loop ticket can subscribe by injecting a runner that tees stdout before resolving — the wrapper's "buffer + parse" contract is unchanged.
- **`AbortSignal` plumbing.** Belongs with whichever layer owns subprocess lifecycle (loop).
- **Adding entries to `SPAWN_ENV_DENYLIST`.** Explicitly deferred to a follow-up "once concrete consumers reveal additional leaks." Resist pre-population — the pin test is the audit gate.
- **Surfacing `exitCode` in the return shape.** Add a wrapper `{ result, exitCode }` when a concrete consumer needs it; today no one does.
- **Wiring `spawnClaude` into `src/loop/`.** That module doesn't exist yet.
