# #35 — `src/github/issues.ts` REST wrappers (getIssue / createIssue / updateIssue)

Second file under `src/github/`. The issue-level read/write surface that the loop and rework flows will call without each caller hand-rolling its own transport. Sibling to #19's `project-client.ts`; consumers come in later tickets.

## Exports

- `GitHubIssuesClient.create(opts, transport)` — synchronous factory; the only entry point. REST endpoints key on `(owner, repo, number)` directly, so there's nothing to resolve up front. Constructor is private.
- `client.getIssue(number)` — `GET /repos/{o}/{r}/issues/{n}`, mapped to the narrow `Issue` shape.
- `client.createIssue({ title, body, labels })` — `POST /repos/{o}/{r}/issues`. Labels pass through as `string[]` (REST takes names natively, no node-ID resolution).
- `client.updateIssue(number, patch)` — `PATCH /repos/{o}/{r}/issues/{n}`. Empty patch resolves to `null` without a transport call. Replace-set semantics on `labels`.
- `Issue` — narrow shape: `number`, `title`, `body`, `labels`, `state`, `url`. No `assignees` / `milestone` / `closedAt` — sibling tickets widen when they need them.
- `CreateIssueInput` — `{ title, body, labels }`.
- `UpdateIssuePatch` — `{ body?, labels? }`.
- `RestTransport` — `(method, path, body?) => Promise<unknown>`. Parallel DI seam to `GraphQLTransport` in #19; the launcher wires both.

## Invariants encoded

- **`!== undefined` patch checks, not truthiness.** `if (patch.body !== undefined)` (not `if (patch.body)`) — callers can legitimately pass `body: ""` to clear the body, or `labels: []` to drop all labels. Test #7 (body:"" is NOT a no-op) is the regression guard against any future "if (patch.body)" simplification that would silently drop empty-string updates.
- **Empty patch is a no-op without a transport call.** `updateIssue(n, {})` resolves to `null` and issues zero transport calls. Test #6 locks BOTH assertions — "no error" alone could be satisfied by silent-catch; "no transport call" alone could be satisfied by returning a fake `Issue`. Together they pin the contract.
- **No `labels: undefined` leakage in PATCH bodies.** `updateIssue(n, { body })` sends `{ body }`, NOT `{ body, labels: undefined }`. Load-bearing: GitHub's REST PATCH replaces the full label set with what is sent, so a leaked `labels: undefined` (or an explicit empty array) would silently strip every label off the issue. Test #3 deep-equals the request body as the canary.
- **Transport rejections propagate verbatim.** No try/catch in the module. Three `it` blocks under `describe("transport errors propagate")` lock the canary substring (`Bad credentials`) for `getIssue` / `createIssue` / `updateIssue` symmetrically.
- **`body: null` from GitHub is mapped to `""`.** GitHub returns `body: null` for issues created without one; the `Issue.body: string` (not `string | null`) contract holds via the `mapIssue` field-level guards. Test #2 locks this.

## Design choices

- **Static factory + private constructor.** Symmetry with `GitHubProjectClient` (#19), even though there's no async ID resolution to gate. Keeps consumers from constructing an instance with a wrong-shape transport, and makes future additions (e.g. resolved repo node ID for sibling helpers) a non-breaking change.
- **Class binds `(owner, repo, transport)` once.** Three free functions would each need an `(owner, repo, transport)` triple, fanning the DI seam across every call site and making "ensure the same transport is reused" a caller-discipline concern. The class shape matches the AC's `getIssue(number)` / `createIssue(...)` parameter shapes with the context implicit.
- **Parallel `RestTransport` instead of reusing `GraphQLTransport`.** REST takes labels by name natively (no node-ID resolution), supports replace-set semantics on `PATCH /issues/{n}` in one call, and keys on `(owner, repo, number)` directly. GraphQL would require an extra labels-by-name query plus add/remove deltas plus a number→nodeId resolution before each mutation. For a "thin wrapper," REST is the right cost.
- **No `@octokit/rest` runtime dep.** The transport is interface-shaped; the launcher decides on the implementation. `package.json` is unchanged in this ticket.
- **`mapIssue` does not throw on malformed input.** Field-level type guards reduce missing fields to safe defaults (`""` / `[]` / `0`), matching `mapItem`'s posture in `project-client.ts:152`. The transport rejecting on a non-2xx response is the deterministic failure boundary; defensive shouting on a successful 200 with a malformed body has not been observed in v2.

## Test surface

`test/github/issues.test.ts`, vitest, RED-first. 12 cases across four `describe` blocks (`getIssue`, `createIssue`, `updateIssue`, `transport errors propagate verbatim`). Each test builds its own routing table inline so a regression points at the exact failing scenario; no shared fixtures across tests.

The three load-bearing rows:

- **Test #3 — partial-body PATCH body equals `{ body: "Updated body" }`.** Locks the no-`labels: undefined` leakage contract. A regression where `labels` unconditionally serializes into the request body would silently replace the issue's labels with an empty set on GitHub.
- **Test #6 — empty patch makes zero transport calls AND resolves to `null`.** The two assertions together pin the AC's "noop, not an error" contract; either alone is forgeable.
- **Test #7 — `body: ""` IS a real update.** Locks the `!== undefined` semantics. A future "if (patch.body)" truthiness simplification would silently drop empty-body updates and break this test immediately.

- Rate-limit tracking. Defer until budget pressure is observed.
