# #61 — `src/claude/jsonl.ts` extractor for last N assistant messages from session JSONL

Second file under `src/claude/`. Lands a single exported async function (`extractLastMessages(jsonlPath, n) → Promise<string[]>`) that reads Claude's on-disk session JSONL, walks each line's `message.content[]`, and returns the last `n` assistant text strings oldest-first. Consumer (not yet built): `src/salvage/` quoting the agent's most recent reasoning into a `max_turns` recovery PR body.

## Why a separate parser from `stream.ts`

The two surfaces consume distinct wire formats and were deliberately kept apart:

- `stream.ts` parses `claude -p --output-format stream-json` stdout — top-level types `"system"` / `"assistant"` / `"result"`, no envelope metadata.
- `jsonl.ts` parses the on-disk session log — envelopes carry `parentUuid` / `sessionId` / `timestamp`, top-level types include `"queue-operation"` / `"user"` / `"assistant"`, no `"result"` line (the session log persists across runs).

`stream.ts`'s `parseStream` returns five fields (cost, sessionId, last message, last N, exitReason). This module returns exactly one thing: the last N assistant text strings. Forcing one parser onto both shapes would complect output contracts or push session-vs-stream discrimination into a caller that has no business knowing about it.

The ~10-line content-walking helper (`extractAssistantText`) is duplicated verbatim across `stream.ts` and `jsonl.ts`. The shared-abstraction tax (third file, new export surface, new import edge) outweighs a single duplication — and the two parsers' invariants could subtly diverge if the SDK changes one wire format and not the other. Reconsider extraction when a third consumer arrives.

## What's filtered

- Top-level envelopes other than `"assistant"` are skipped (drops `"queue-operation"`, `"user"`, and anything else the session log carries).
- Inside an assistant envelope, only `block.type === "text"` blocks with a non-empty string `text` are taken. `tool_use` and `thinking` blocks are excluded by design — `thinking` because it's the agent's internal monologue and the PR section's framing ("Last messages from the agent") implies user-facing output. Symmetric with `stream.ts`'s `tool_use` exclusion.

## Regression posture (PR #138 pin)

The load-bearing test is `test/claude/jsonl.test.ts` group 1 — `extractLastMessages(FIXTURE_PATH, 5)` against the captured fixture asserts `length > 0`, every element is a non-empty string, and no element contains `"type":"tool_use"` or `"type":"thinking"`. This is the test that, had it existed in v1, would have caught PR #138's silent-empty `**Last messages**` section. The empty-section bug shipped because the v1 test asserted only "does not throw."

Per `docs/lessons.md`'s regression-fixture rule (frozen 2026-05-11 but still authoritative): observed parser bugs become permanent fixture-driven assertions. `test/fixtures/claude-jsonl/session.jsonl` is a real session capture, checked in verbatim. The "verbatim" rule applies only to that captured file; the structural tests (groups 2–6) author synthetic JSONL inline via tmp files — same pattern as `stream.test.ts`'s `lastN behaviour` group.

## Error policy

- Malformed / truncated line → skipped silently (per-line `try`/`catch` around `JSON.parse` only; no wrap around the loop). Mirrors `stream.ts`.
- Line that parses to a non-object (`null`, `42`, `[1,2,3]`) → skipped.
- `message.content` missing or not an array → that line yields zero texts.
- Empty file → `[]`.
- `n <= 0` → `[]` (negative clamps to 0).
- File missing / permission denied → `readFile` rejection propagates. **Not caught.** The salvage caller owns path discovery and is the right layer to verify the path exists. Per CLAUDE.md "don't write a defense for a failure mode that hasn't been observed" — the only observed v1 regression was the empty-output bug, not a missing-file bug. Add an `ENOENT → []` fallback only if a future ticket demonstrates salvage's discovery is unreliable.

## Patterns established by this ticket

- **Wire-format parsers stay separated under `src/claude/`.** One file per Claude-emitted format. Even when content-walking sub-steps look identical (`extractAssistantText` in both `stream.ts` and `jsonl.ts`), duplicate them rather than extract — until a third consumer arrives. The independent invariants protect against unilateral wire-format drift.
- **Captured fixture + non-empty assertion is the regression contract for parser bugs.** Following `stream.ts`'s precedent: when an observed bug had the shape "parser silently emitted empty/wrong content," the fix-forward test asserts *positive* output content (`length > 0`, type checks, leak-shape negative-contains), not "does not throw." Synthetic inputs cover structural / algorithmic assertions; the captured fixture pins the field-shape contract with the SDK.
- **Path validation lives at the discovery layer, not the parser.** `extractLastMessages` takes a fully-resolved path and lets `readFile` errors propagate. Salvage owns "which session file maps to which run"; that layer is also where missing-file recovery (if ever needed) belongs.

## Out of scope (deferred follow-ups)

- Wiring `extractLastMessages` into `src/salvage/`. That module doesn't exist yet.
- Discovering which session file corresponds to a given dispatch run (encoded-cwd traversal, session-id mapping). Salvage's discovery layer.
- Rich per-message metadata (`{ role, timestamp, parentUuid }`). If a future surface needs it, add an `extractLastMessagesWithMeta` sibling export rather than widening this return shape.
- Streaming / incremental parse. Session files are bounded by Claude's per-run context.
- Lifting `extractAssistantText` to a shared module — defer until a third consumer.
- Catching `ENOENT` and returning `[]` — defer until observed.
