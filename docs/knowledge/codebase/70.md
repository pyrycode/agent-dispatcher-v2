# #70 — `src/salvage/last-messages.ts` PR-body section composer

Second file under `src/salvage/`. Composes the `**Last messages from the agent:**` section that the (not-yet-built) salvage PR-body builder will splice into a `max_turns` recovery draft. Thin formatter around `extractLastMessages` from [`src/claude/jsonl.ts`](../../../src/claude/jsonl.ts) ([#61](61.md)) — owns the Markdown shape and the missing-file → placeholder contract, nothing else.

## Export

- `composeLastMessagesSection(jsonlPath: string, n: number): Promise<string>` — calls the extractor inside `try`, renders each returned string as a GitHub blockquote (every line prefixed `> `, blank lines within a turn rendered as bare `>`), joins turns with `\n\n---\n\n`, and prepends the literal header `**Last messages from the agent:**\n\n`. Empty result (extractor returned `[]` **or** rejected) renders the placeholder `_(no assistant messages captured)_` in place of the body. No trailing newline — caller owns surrounding whitespace.

## Render shape (pinned by `toBe` in tests)

Two turns `"a"` and `"b"`:

```
**Last messages from the agent:**

> a

---

> b
```

Empty / missing / placeholder case:

```
**Last messages from the agent:**

_(no assistant messages captured)_
```

A turn whose text contains a blank line renders the bare `>` for that empty line — not `> ` with a trailing space.

## Catches all extractor rejections, not just `ENOENT`

The AC says "empty/missing file → empty section, does not throw." The composer reads this as the broader contract: any `readFile` failure (`ENOENT`, `EACCES`, `EISDIR`, …) becomes the placeholder render. Two reasons:

1. From the operator scanning the PR, "couldn't read the file" and "file was empty" are indistinguishable and equivalent — both mean "no content to quote." Differentiation belongs in dispatcher logs, not the PR body.
2. The salvage flow is itself a recovery surface. An exception while building a recovery PR escalates a `max_turns` event into a dispatcher crash. The composer's failure-mode budget is "render placeholder," not "rethrow."

If a future ticket needs per-error-code differentiation (e.g. monitoring counts `ENOENT` vs `EACCES`), thread an `onError` callback then — not now.

## No escaping of agent text

The extractor returns the agent's raw text. The composer does not escape Markdown inside it. If a turn contains `---` on its own line, it renders as `> ---` (a quoted dash-rule line; the `> ` prefix wins over the horizontal-rule interpretation). If a turn contains a triple-backtick fence, it renders as `> ```…` — GitHub preserves fence syntax inside a blockquote. Escaping was deliberately rejected: it risks corrupting agent-emitted Markdown and creates a maintenance surface for a problem we haven't observed.

## Why blockquote + `---` separator (not fenced code, not bare paragraphs)

- **Blockquote** scopes agent prose visually so an agent-emitted `## heading` can't break the PR body's outline. Bare paragraphs would let agent content collide with the PR body's structure.
- **Horizontal rule between turns** because adjacent GitHub blockquotes merge into one visual block. The `---` is the cheapest way to make turn boundaries legible.
- **No fenced code block** because agent text frequently *contains* fenced code, and nesting fences in Markdown is brittle. Blockquotes don't have that problem.

## `renderTurn` stays private

One helper, kept module-local. If a second surface needs to render a single agent turn (e.g. a Slack notification body), extract then. Two consumers don't exist yet — same rule that kept `extractAssistantText` duplicated across `stream.ts` and `jsonl.ts` until a third consumer arrives ([#61](61.md)).

## Patterns established

- **The composer owns its layer's recovery contract, not the layer below.** `extractLastMessages` deliberately propagates `readFile` rejections ([#61](61.md)'s "path validation lives at the discovery layer" pattern). This module is that next-layer-up — it sits between the parser and a higher-level orchestrator, and it's where the AC's "does not throw" contract gets honoured. Same shape applies to any future formatter wrapping a strict parser: catch at the layer whose AC promises tolerance, not at the parser.
- **Pin format contracts with full-string `toBe`, not substring checks.** Test group 2's exact-string equality against the assembled output locks the header, the blank-line policy, the blockquote prefix, the separator shape, and the turn ordering in one assertion. A future "clean up the rendering" PR breaks this loudly rather than silently shifting the section's shape. Substring/regex checks would let drift through.
- **Sibling export for a new render surface, not parameterisation.** No `formatOpts` / `style: "markdown" | "plain"` knob. If a future surface needs a different rendering (Slack plain-text, JSON metadata), add a sibling export rather than parameterising this one. Mirrors [#61](61.md)'s "add `extractLastMessagesWithMeta` if metadata is needed" posture.

## Out of scope (deferred follow-ups)

- Wiring `composeLastMessagesSection` into the salvage PR-body builder. That builder doesn't exist yet; its ticket will import from this file.
- Discovering which session JSONL corresponds to a given salvaged dispatch run (encoded-cwd traversal, session-id mapping). Salvage's discovery layer.
- Per-turn length capping. The salvage caller picks `n` (count of turns) but has no `maxChars` knob. Add a per-turn ellipsis truncation only if reviewers report PRs hard to scan because turns are too long.
- Logging when the file is missing. Belongs at the orchestrator where the path was resolved and the broader recovery context is available.
- Differentiating `ENOENT` from `EACCES` etc. in the catch. Add an `onError` callback only if a real consumer demonstrates the need.
