# #3 — `src/config/env.ts`: .env loading + validation

Adds the dispatcher's single source of truth for environment configuration. Two exports:

- `parseConfig(env: Record<string, string | undefined>): Config` — pure validator. All branch tests target this.
- `loadConfig({ agentsRoot }): Config` — thin I/O wrapper: read `<agentsRoot>/.env`, layer non-empty `process.env` on top, hand the merged record to `parseConfig`.

Returned `Config` is `Object.freeze`d (runtime guard) and every field is `readonly` (compile-time guard). `salvageGates` is a frozen `readonly string[]`; shallow freeze is sufficient because every field is a primitive or a frozen primitive array.

## Conventions established

- **Pure core + thin I/O wrapper** — same shape as `paths/agents-root.ts` and `paths/target-root.ts`. Tests live on the pure core; the wrapper gets a small smoke test.
- **Empty-string env values are treated as unset everywhere** — both inside `parseConfig` (a stray `KEY=` line in `.env` reads as `""` → `undefined` to the validator) and inside `loadConfig` (an explicit `KEY=""` in `process.env` does NOT override `.env` values). The `loadConfig` filter is a deliberate deviation from a naive `{...fileEnv, ...process.env}` merge — see the comment on `loadConfig` for the why.
- **Error message contract** — `Missing required env var: <KEY>`, `Invalid <KEY>: expected integer, got "<raw>"`, `Invalid <KEY>: must be >= <min>, got <n>`, `Invalid OWNER_TYPE: expected "user" or "organization", got "<raw>"`. Downstream callers can string-match if needed.
- **`GITHUB_TOKEN` redaction is contractual** — the value never appears in any error message. The module only validates non-empty for `GITHUB_TOKEN` (no shape check) precisely so no future error path can echo it. Lock-in test (`token redaction`) asserts this for every throw site that runs after the token is read.

## Var coverage

| Var | Required? | Validation | Default |
| --- | --- | --- | --- |
| `GITHUB_OWNER` | yes | non-empty string | — |
| `GITHUB_REPO` | yes | non-empty string | — |
| `PROJECT_NUMBER` | yes | integer ≥ 1 | — |
| `GITHUB_TOKEN` | yes | non-empty string; **never echoed in errors** | — |
| `OWNER_TYPE` | no | exactly `"user"` or `"organization"` (case-sensitive) | `"user"` |
| `TARGET_REPO_PATH` | no | non-empty string when set; no path resolution here | `undefined` |
| `TARGET_DEFAULT_BRANCH` | no | non-empty string | `"main"` |
| `SALVAGE_GATES` | no | split on `;`, trim, drop empties | `[]` (see [ADR 0002](../decisions/0002-salvage-gates-default-empty.md)) |
| `PYRY_MAX_CONCURRENT` | no | integer ≥ 1 | `2` |
| `DISCORD_WEBHOOK_URL` | no | non-empty string when set; no URL-shape check | `undefined` |
| `PYRY_LOG_RETENTION_DAYS` | no | integer ≥ 0 (`0` disables rotation) | `30` |

`AGENTS_REPO_PATH` is intentionally NOT consumed here — the launcher reads it via `paths/agents-root.ts` to locate `.env` before this runs. Putting it in `.env` would be a chicken-and-egg loop.

## `.env` parser

Tiny private `readEnvFile` (~20 lines). Handles comments, blank lines, and a single surrounding pair of double or single quotes. Does **not** handle backslash escapes, multi-line values, `${VAR}` interpolation, or trailing inline comments (`KEY=value # comment` reads value as `"value # comment"`). v1 didn't need any of these; escalate if a future ticket does.

Node 22's `process.loadEnvFile` was rejected: it mutates `process.env` globally and returns nothing — incompatible with a pure pipeline module and untestable without test-pollution cleanup.

## Out of scope (deferred)

- Schema-validation libraries (zod, valibot) — the module is small and flat. Revisit if field count crosses ~25.
- Multi-environment `.env.production` / `.env.local` layering — single `.env` is the v1 contract.
- URL-shape validation for `DISCORD_WEBHOOK_URL`.
- Logging / debug output — `loadConfig` returns a value or throws; the launcher decides what to print.
- Consuming `Config` from any module — pure leaf.
