# #31 — `src/pipeline/routing.ts` `decideReworkRouting`

The routing half of `src/pipeline/` — sibling to `decideLabelDelta` (#5) and `selectDispatches` (#30). Pure function over a ticket's labels: returns which agent to re-run for a `needs-rework:*` ticket and which stale `ready:*` / `wip:*` / `error:*` labels to strip so the target runs on a clean slate. Mirrors v1's `runReworkRouting` strip contract.

## Exports

- `decideReworkRouting(labels): { target, stripLabels }` — pure, never throws. `target: Agent | null`, `stripLabels: readonly string[]`. No `needs-rework:*` label → `{ target: null, stripLabels: [] }` (caller's no-op).
- `Agent` — derived from `Label` via `type ExtractAgent<L> = L extends 'needs-rework:${infer A}' ? A : never`. Single source of truth lives in `transitions.ts`; adding a new `needs-rework:<x>` member of `Label` widens `Agent` automatically with no second site to update. Today: `"po" | "architect" | "developer" | "code-review"`. **Distinct from `Agent` in `selection.ts`** (column-consumer union, includes `"documentation"`) and from `AgentName` in `blockers.ts` (commit-producer union). Three narrow types per the #6 narrow-types rule — overlapping today, structurally distinct concerns. Promote only when a fourth caller needs the union of two.
- `ReworkRouting` — `{ readonly target: Agent | null; readonly stripLabels: readonly string[] }`.

## Why the input is `readonly string[]`, not `readonly Label[]`

`wip:*` and `error:*` are intentionally absent from the narrow `Label` union (per `transitions.ts` and #5 / #24). They're dispatcher run-state, not transition triggers. This function is the boundary where dispatcher state crosses a pure predicate; widening `Label` to admit them would break the dead-letter invariant in `decideLabelDelta`'s tests. So the function accepts arbitrary GitHub label strings and prefix-matches.

## Why this is separate from `decideLabelDelta`

`decideLabelDelta` (#5) already strips `ready:*` and `needs-rework:*` per the transitions table. It does **not** touch `wip:*` / `error:*` — those aren't transition triggers. Rework routing is the only place that surfaces them, so it owns the strip list. The two functions compose at the dispatcher seam: `decideReworkRouting` produces the strip set when re-routing, `decideLabelDelta` produces add/remove for any subsequent state transition.

## Why `needs-rework:<target>` is NOT in `stripLabels`

The dispatcher consumes it downstream when promoting the ticket to `wip:<target>`. Stripping it here would race against that promotion. The function preserves it explicitly (`l !== reworkLabel` filter clause), even though it begins with a strip-eligible-looking prefix.

## Algorithm

1. Linear scan for the first label matching `needs-rework:<x>` with non-empty `<x>`. First-by-input-order wins; the dispatcher's normal-path invariant (`decideLabelDelta`'s strips) keeps `≤1 needs-rework:*` per ticket, so the tiebreak is deterministic but rarely exercised.
2. If none found, short-circuit to `{ target: null, stripLabels: [] }`.
3. Otherwise filter `labels` for those starting with `ready:` / `wip:` / `error:`, excluding the captured rework label itself. Preserve input order; do not dedupe (caller owns the GitHub label API contract).

## Edge cases

- **Multiple `needs-rework:*` labels** — first by input order wins. Test `multiple needs-rework:* labels — first by input order wins` pins this so a future drift surfaces.
- **Malformed bare `needs-rework:`** (empty suffix) — treated as not-a-rework-label. The closed `Label` union has no empty-suffix member, so this only happens via manual edits; silently ignoring routes through the no-op path rather than crashing the loop. Per CLAUDE.md § "Don't write a defense for a failure mode that hasn't been observed", we don't validate the suffix against `Agent`'s literal set — runtime validity is structurally guaranteed by the `Label` producers.

## Test surface

`test/pipeline/routing.test.ts`, vitest, RED-first. ~85 lines, four `describe` blocks (no-rework / target-resolution / strip-contract / edge-cases).

- **Target resolution** uses `it.each(REWORK_LABELS)` over a hand-listed copy of the closed set (`po`, `architect`, `developer`, `code-review`). TS literal types erase at runtime, so the closed set is mirrored in the test as a `const` tuple — comment references `transitions.ts:48-51` so the next contributor knows where to add a new entry.
- **Structural invariant** iterates `REWORK_LABELS` and asserts `target` is non-null and equals the suffix. This is the catch for "future ticket adds `needs-rework:documentation` to `Label` but forgets to extend the test fixture" — the invariant fails the suite if `Agent`'s derived literal set drifts from `REWORK_LABELS`.
- **Strip-contract fixture** (`["ready:architect", "wip:developer", "error:max-turns", "needs-rework:architect", "size:s", "priority:high", "security-sensitive"]`) is shared across three assertions: positive (every `ready:*` / `wip:*` / `error:*` is stripped, in input order), negative-rework (`needs-rework:architect` not in `stripLabels`), negative-survivors (`size:s`, `priority:high`, `security-sensitive` not in `stripLabels`). One fixture, three angles — keeps the test readable without re-stating the input.

## Out of scope (deferred follow-ups)

- Wiring `decideReworkRouting` into the dispatcher loop. `src/loop/` and `src/dispatch/` haven't landed; the rework strip is invoked at the post-review seam, alongside the `wip:<target>` promotion.
- Validating the captured suffix against `Agent`'s literal set. The cast through `Agent` is structurally safe (only `Label` members produce `needs-rework:*` labels in the system), and CLAUDE.md forbids defenses for unobserved failure modes.
- Deduping or normalizing `labels`. GitHub's label API guarantees uniqueness; `ProjectItem.labels` from #19 is already a set.
- A `needs-rework:documentation` row. No observed transition routes back into documentation as a rework target — widen `Label` and add the row when needed.
- Promoting `Agent` into a shared module. Two pipeline files own narrow `Agent` types today (`routing.ts`, `selection.ts`); a shared union would conflate column-consumer with rework-target, which are structurally distinct concerns. Defer until a third caller genuinely needs both.
