# #2 — `src/paths/` resolvers

Landed two pure-function path resolvers under `src/paths/`. First real module after the scaffold.

## What shipped

- `src/paths/agents-root.ts` — `resolveAgentsRoot({ envValue, fallback })` returns an absolute path.
- `src/paths/target-root.ts` — `resolveTargetRoot({ envValue, agentsRoot })` returns an absolute path.
- `test/paths/agents-root.test.ts`, `test/paths/target-root.test.ts` — vitest, pure string inputs (no fs).

## Resolution order (both resolvers)

1. Non-empty `envValue` → `resolve(envValue)`.
2. Else non-empty fallback (`fallback` for agents-root, `agentsRoot` for target-root → `resolve(agentsRoot, "..")`).
3. Else throw, naming the env var the operator can set.

Empty-string env counts as unset. A stray `AGENTS_REPO_PATH=` line in `.env` reads as `""`, not `undefined`.

## Non-obvious shape decisions

- **`agents/` lives INSIDE the target repo** — target = `parent-of(agentsRoot)`, not a sibling. v1 bug fixed in commit `c72adb4`; lock-in test prevents regression.
- **No launcher-relative fallback** for agents-root. v1's `__dirname + "../.."` offset doesn't port — v2 source ships from its own repo with no fixed positional relationship to consumers. The `fallback` parameter stays so tests can exercise the second branch and a future caller can derive one. See [decisions/0001-agents-root-fallback-shape.md](../decisions/0001-agents-root-fallback-shape.md).
- **No `process.env` reads, no `__dirname` capture, no `await`** — those land at the call site (`src/dispatch/`, when it lands). Resolvers depend only on `node:path`.

## Out of scope

- `resolveDefaultBranch` — ships with `src/config/`.
- Wiring into `src/index.ts` barrel — populates module-by-module as consumers arrive.
