# #43 — `src/worktree/cleanup.ts` `removeWorktree` (idempotent) + collision auto-recovery

First file under `src/worktree/`. One idempotent worktree-removal primitive with built-in auto-recovery for the branch/path collision edge case, plus a pure parser exported for unit testing the locate step. The post-run cleanup phase and the (future) create-time collision-retry path both call `removeWorktree(path, spawn)` instead of inlining `git worktree remove --force` at every site — v1's leak-and-stale-collision pain mode lifted into one helper.

## Exports

- `removeWorktree(path: string, spawn: Subprocess): Promise<void>` — idempotent. Path-doesn't-exist on disk is a noop with **zero spawn calls** (load-bearing AC pin); path-exists-but-not-registered is a noop after one (failed) `git worktree remove` and one `list --porcelain`. Throws only if the diagnostic list call fails or the recovery's force-remove fails (and, once locate-by-branch lands at the create-collision callsite, if the post-recovery retry fails).
- `findCollidingWorktree(porcelain: string, targetPath: string): string | null` — pure. Splits on `\r?\n\r?\n`, walks each block's lines, returns `targetPath` when an entry's `worktree <p>` exactly equals `targetPath`, else `null`. Exact equality, no normalisation.
- `Subprocess` — DI seam type: `(argv: readonly string[]) => Promise<SubprocessResult>`.
- `SubprocessResult` — `{ exitCode, stdout, stderr }` (all `readonly`).

`pathExists` is file-local (`access` from `node:fs/promises` wrapped in try/catch).

## Invariants encoded

- **Filesystem fast path is the noop gate.** AC pins `t.calls.length === 0` when `path` doesn't exist. Two candidate gates: `fs.access` first (zero spawn calls — chosen) vs `git worktree list --porcelain` first (one call — fails the AC). The false-positive on stale-registered (path missing on disk but still in `git worktree list`) is `git worktree prune`'s concern, not ours.
- **`Subprocess` MUST resolve on non-zero exit, not reject.** Contract: the function classifies exit codes and a rejection would bypass the recovery branches. Tests enforce by routing-table mock that always resolves; production wiring (future ticket) wraps `child_process.spawn` and resolves on `'close'` regardless of exit code.
- **`findCollidingWorktree` returns null or exact target — no first-entry fallback.** Critical safety property surfaced during code review (commit `d251f1c`): the first block of `git worktree list --porcelain` is conventionally the repository's main worktree; a "best-effort, return first entry on miss" fallback would let `removeWorktree` force-remove the main repo on a parser miss. The exact-match-or-null shape forces callers (and the recovery branch) to treat "couldn't locate" as a noop after the diagnostic call rather than a destructive guess. The third pure-parser test (`first-entry-fallback regression guard`) is the canary.
- **Recovery is bounded — one force, one retry.** No unbounded loop. After a successful force-remove, if `conflict === path` the retry is skipped (force already removed our target); otherwise the original removal is retried exactly once. AC's "retry-still-fails surfaces error verbatim" branch is unreachable today (with exact-match-or-null, any non-null conflict equals the target so the short-circuit always fires); it becomes reachable when the locate-by-branch half lands at the create-collision callsite (separate ticket).
- **Errors propagate with stderr verbatim** (`.trim()`-ed only to dodge trailing newlines). Mirrors `labels.ts`'s "no catch around transport" posture. `Subprocess` rejection itself propagates raw — that's a contract violation, surfacing it loudly is correct.
- **`pathExists` access errors are treated as "doesn't exist" → noop.** No filesystem-permission errors are surfaced; if the worktree path is in a directory the dispatcher can't read, the cleanup couldn't have completed anyway.
- **Locate-by-path only.** The AC's "or registered branch" half is a future extension when the create-collision callsite supplies a branch (it knows which branch it tried to add). Adding a `branch?: string` parameter today speculates on the future signature.

## Design choices

- **Free function, not a class.** No state to cache, no precondition to protect. `project-client.ts` (#19) / `issues.ts` (#35) / `labels.ts` (#36) / `pr.ts` (#41) bind transport + (owner, repo[, repositoryId]) once because they have state; this primitive doesn't. A `WorktreeCleanupClient.create(spawn)` factory would buy zero semantic gain.
- **`Subprocess` is a fresh seam shape, NOT a reuse of `RestTransport` or `GraphQLTransport`.** `RestTransport` is HTTP-shaped (`(method, path, body) => unknown`); `GraphQLTransport` is GraphQL-shaped (`(query, variables) => unknown`); `Subprocess` is shell-shaped (`(argv) => { exitCode, stdout, stderr }`). Forcing one to model another adds a translation layer at every implementation site. Per the #6 narrow-types rule, each I/O boundary owns its narrow type for its narrow concern. The `Subprocess` type stays co-located in `cleanup.ts` until a second `src/worktree/` (or other subprocess) caller appears — same one-shared / second-imports / third-promotes ladder as `GraphQLTransport`.
- **`pathExists` is private, not a seam.** AC #3 names "subprocess invocation" — fs reads are out of scope. Adding a second seam doubles the API surface for marginal test ergonomics; real temp dirs in `beforeEach` (`mkdtempSync` + `rmSync`) are the established pattern.
- **Asymmetry with `removeLabel`'s idempotency gate.** `removeLabel` (#36) is GET-then-PUT-only-if-present (always one call); `removeWorktree` is fs-exists-then-spawn-only-if-present (zero calls when absent). Same idempotency contract, opposite cost ranking — the subprocess seam has real cost (process spawn) where a single REST POST does not, and the AC is loud about zero calls.
- **Pure parser exported.** `findCollidingWorktree` is testable without the seam — same posture as `parseCommitsAhead` in `blockers.ts`. Three pure-parser tests live in their own `describe` block (`multi-block`, `empty porcelain`, `no first-entry fallback regression`); integration tests live in `describe("removeWorktree", ...)`.
- **Exact equality, no `path.resolve` normalisation.** The caller passes the same path it gave to `git worktree add`, and `git worktree list` echoes that path verbatim. Per #6 set-intersection-style-predicates, normalisation belongs at the caller (the dispatcher's worktree-path builder is the canonical source) — the parser stays a string-equality predicate.

## Test surface

`test/worktree/cleanup.test.ts`, vitest, RED-first per CLAUDE.md. 7 `it` blocks across two `describe`s plus an inline `makeSpawn(routes)` helper that mirrors `test/github/labels.test.ts:9-37` retyped to `Subprocess`. Real temp dirs via `mkdtempSync` in `beforeEach` for "path exists" branches; `randomBytes`-generated never-created paths for the absent branch.

The load-bearing rows:

- **`already-absent — zero subprocess calls`.** `path` is a never-created tmp path; **no routes registered** so any spawn call would hit `No route matched: ...` and fail the test. Pin: `t.calls.length === 0`. The AC's load-bearing assertion; a future "always shell out for symmetry" simplification still satisfies "no throw" but fails this count.
- **`collision triggers locate→force-remove→retry-skip when conflict===path`.** Pin: `t.calls.length === 3` (NOT four — verifies the `conflict === path` short-circuit). The recovery's three calls in order: bare remove (fails) → `list --porcelain` (succeeds with porcelainBlock fixture) → `--force` remove on the parsed conflict path.
- **`collision then list fails — surfaces stderr verbatim`.** Stand-in for the AC's "retry-still-fails" branch (unreachable today per the exact-match-or-null invariant). Routes the post-collision `list --porcelain` to `fail("CANARY: list refused")`; pins that `caught.message` contains the canary string verbatim. Same posture as `labels.test.ts` "transport-failure THROWS".
- **`findCollidingWorktree no first-entry fallback regression guard`.** Two-block porcelain where the first block is `/Users/foo/repo` (refs/heads/main) and the second is `feature/77`; target is `/some/other/path`. Pin: returns `null`, NOT the first block's path. A future "best-effort fallback" simplification would force-remove the main repo on a parser miss and fail this test immediately.

No real `git` invocations; no `child_process` import in either source or test (per AC #3 — verified by inspection).

## Out of scope (deferred follow-ups)

- Wiring `removeWorktree` into the loop's post-run cleanup phase or the create-time collision-retry path. Consumers land in their own tickets.
- Production `Subprocess` implementation (a `child_process.spawn` wrapper that collects stdout/stderr and resolves on `'close'` regardless of exit code). Lands in the launcher ticket.
- Locate-by-branch — extending `findCollidingWorktree` (or adding a sibling) to match by registered branch ref. The create-collision callsite knows the branch name it tried to add and will drive this when it lands. Today's by-path match covers the post-run cleanup case.
- A sibling `worktree/add.ts` for `git worktree add` with collision-detect + auto-recovery composing `removeWorktree`. Lands when the dispatch flow needs the create half.
- Promoting `Subprocess` / `SubprocessResult` from `cleanup.ts` to a shared `src/runtime/subprocess.ts` (or similar). Defer until a third caller exists or a cross-package import surface emerges — same one-shared / second-imports / third-promotes ladder as `GraphQLTransport`.
- A `pruneStaleWorktrees()` primitive (`git worktree prune` wrapper). Different contract; out of scope for this ticket.
- Path normalisation inside `findCollidingWorktree` (symlink resolution, trailing-slash tolerance). Add only when an observed real-world drift demands it.
