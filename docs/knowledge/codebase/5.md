# #5 — `src/pipeline/decisions.ts` `decideLabelDelta`

The single label-mutation site every transition routes through. Pure function: `(before, after) → { add, remove }` consults `TRANSITIONS` from #24, applies the row's `strips` patterns plus the after-state's labels, encodes no transition-rule logic of its own. Per CLAUDE.md § "decideLabelDelta is the only place labels mutate", every future caller (pre-dispatch, post-run cleanup, rework routing, done-cleanup) reads from this function — adding a fifth call site is the smell that means a transition row is missing, not that a fifth helper is needed.

## Exports

- `decideLabelDelta(before, after)` — pure function; throws on illegal `(from, to)` with both column names in the message so call sites can attribute the failure. No fallback to "no-op delta" — an unrecognized transition is a programmer bug, same fail-fast posture as `parseCommitsAhead` in `blockers.ts`.
- `TransitionState` — `{ column: Column; labels: readonly Label[] }`. Narrow on purpose: `Label` is the closed union from `transitions.ts`; `wip:*` / `error:*` / `size:*` / `priority:*` / `security-sensitive` are dispatcher-run lifecycle / metadata, not transition triggers, and stay out until a transition consumes one.
- `LabelDelta` — `{ add: readonly Label[]; remove: readonly Label[] }`. By construction `add ⊆ after.labels` and `remove ⊆ before.labels` — the function strips, never synthesizes. Triggers come from the agent's run output via `after.labels`.

## Algorithm

1. `TRANSITIONS.find` over `(from, to)`. Linear scan — 19 rows; no profiler will care.
2. Throw on no match with both column names verbatim.
3. `remove` = labels in `before.labels` NOT in `after.labels` whose name starts with one of `row.strips`'s prefixes (trailing `*` sliced off, mirroring `hasNeedsReworkLabel`'s `startsWith` idiom in `blockers.ts:62`). Forward auto-advance rows have `strips: []` → `remove` is structurally empty.
4. `add` = labels in `after.labels` NOT in `before.labels`.

The `(b)` clause in the `remove` filter ("not in `after.labels`") is what makes the function honor caller intent — if an after-state still carries a label, the function doesn't fight the caller and strip it.

## Test surface

`test/pipeline/decisions.test.ts`, vitest, RED-first. Four `it` blocks, ~170 lines.

- **Per-row coverage (load-bearing).** An `EXPECTED` literal map carries one entry per `TRANSITIONS` row. Two iteration tests: one asserts every `TRANSITIONS` row has an `EXPECTED` entry (missing key = test failure naming the gap), one asserts the delta matches. Adding a row to the table without a matching `EXPECTED` entry fails the suite immediately — that's the structural guarantee the "single mutation site" rule depends on.
- **Illegal-transition throws** via `it.each` with three `(from, to)` pairs. Regex assertion on the throw message locks the both-columns-in-error contract.
- **Invariant: `add ⊆ after.labels`** (no synthesis) over every `EXPECTED` row.
- **Invariant: `≤1 ready:*` and `≤1 needs-rework:*` after applying the delta** to the before-state, over every `EXPECTED` row.

## Out of scope (deferred follow-ups)

- Wiring `decideLabelDelta` into any consumer. Pre-dispatch (`src/dispatch/`), post-run cleanup (`src/loop/`), rework routing (#7's `decideReworkRouting`), done-cleanup — each lands in its own ticket.
- A non-throwing `findTransition(from, to): Transition | null` variant. Add when a real call site asks "is this legal?" without wanting to act on the answer.
- An `extraStrip: LabelPattern[]` parameter for one-off cleanup. The whole point of "decideLabelDelta is the only place labels mutate" is that strip patterns are owned by the transition table, not by callers.
- `wip:*` / `error:*` handling. Agent-run lifecycle, not transition triggers; widening `Label` would force fake `requires` rows in the table (see #24's spec § "wip:* and error:* are intentionally absent").
- De-duplicating `before.labels` / `after.labels`. Caller-trust at the boundary; the GitHub label API guarantees uniqueness and `ProjectItem.labels` from #19 is already a set.
- A `### decideLabelDelta (#5)` patterns entry in `docs/PROJECT-MEMORY.md`. Deferred per the architect's branch-overlap call to avoid guaranteed merge conflicts at integration time.
