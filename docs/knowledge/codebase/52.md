# #52 — `src/pipeline/auto-advance.ts` `decideAutoAdvance`

Sixth file under `src/pipeline/` (after #6, #25, #24, #30, #31, #46). Lands the `decideAutoAdvance.backlog_cap` term of CLAUDE.md's throughput equation — a pure decision function that promotes `Backlog → In Architecture` up to a capacity bound.

## Exports

- `AutoAdvanceState` — narrow input: `{ items: readonly SelectionItem[] }`. Mirrors `SelectionState` in `selection.ts`.
- `AdvanceDecision` — `{ readonly issueNumber: number; readonly to: Column }`. `Column` imported from `./transitions.ts`. For this slice `to` is always `"In Architecture"`.
- `decideAutoAdvance(state, inFlightCount, maxConcurrent): AdvanceDecision[]` — walks `state.items` in caller-supplied order, filters by eligibility, emits decisions up to `Math.max(0, maxConcurrent - inFlightCount)`.

## Eligibility

Four conjuncts checked in cost order (cheapest first; short-circuits on the most common failures):

1. `item.column === "Backlog"` — non-Backlog rows dominate `state.items` in steady state.
2. `item.labels.includes("ready:po")` — Backlog rows without `ready:po` are still triaging.
3. `!hasWipLabel(item.labels)` — `wip:*` prefix match.
4. `!hasOpenBlockers(item.blockers)` — array walk over blockers (the costly one).

## Why the throughput equation needs both terms parameterised (the v1 incident)

In v1 `decideAutoAdvance` hardcoded `WIP=1` while `selectDispatches` correctly took `maxConcurrent` as a parameter. Bumping the dispatch cap silently failed because auto-advance still clamped to 1 — Backlog promotion was the binding gate. The v2 rule is that every term in `actual_wip = min(selectDispatches.cap, decideAutoAdvance.backlog_cap, blocker_chain, MANUAL_ADVANCE_GATES)` takes `maxConcurrent` as input, so a single configuration value controls throughput end-to-end. Adding a new gate means adding both a `min(...)` term and an audit pass over the existing ones.

## `AdvanceDecision.to` is explicit even though it's a constant today

`to` is always `"In Architecture"` in this slice but is emitted in the decision so the caller's `decideLabelDelta(before, after)` invocation needs no out-of-band lookup. When follow-up slices add `In Architecture → In Development` and the other forward auto-advance pairs, this shape extends without a breaking change — only the constant inside `decideAutoAdvance` (or its successor) changes.

## `SelectionItem` reused, not redeclared

`SelectionItem` from `selection.ts` already encodes the exact `{ column, issueNumber, labels, blockers }` shape this function needs. The AC explicitly forbids declaring a parallel type. The output type stays distinct (`AdvanceDecision` vs `DispatchTuple`) — different consumers need different routing data.

## `hasWipLabel` duplicated from `selection.ts`, not promoted

The three-line `labels.some((l) => l.startsWith("wip:"))` helper is copied rather than exported. Same shape rule as `hasNeedsReworkLabel` across `blockers.ts` / `routing.ts` / `branch-setup.ts` (#46): two call sites with one stable prefix is cheaper than premature centralisation. Promote to `src/pipeline/labels.ts` if a third pipeline module needs the same predicate.

## Capacity formula handles every edge case in one expression

`capacity = Math.max(0, maxConcurrent - inFlightCount)` collapses:

- `maxConcurrent = 0` → `capacity = 0` (regardless of `inFlightCount`).
- `inFlightCount > maxConcurrent` (transient mid-cycle) → `capacity = 0`, no throw.
- `inFlightCount < 0` (cannot happen from a GitHub count, but harmless if it ever did) → `capacity > maxConcurrent`, the for-loop's `>= capacity` still terminates.

No separate negative-input guard; the `selection.ts:69` `if (maxConcurrent <= 0) return [];` pattern doesn't apply here because capacity is a derived value, not the parameter itself.

## Test surface

`test/pipeline/auto-advance.test.ts`, vitest, RED-first. Two `describe` blocks — capacity bounds (5 cases) and ineligibility filters (4 cases). Tests assert exact array shape (e.g. `[{ issueNumber: 1, to: "In Architecture" }]`), not `toHaveLength` — the `to` field is part of the contract.

What is NOT tested here (covered elsewhere):

- Every `wip:*` suffix variant — `selection.test.ts` covers the prefix-match invariant.
- `hasOpenBlockers` edge cases (mixed OPEN/CLOSED states) — `blockers.test.ts`'s domain.
- A standalone "preserves input order" case — already covered structurally by `both-advance-same-cycle` and `partial-in-flight-reduces-capacity`.
