# #24 — `src/pipeline/transitions.ts` legal-transitions table

Single typed source of truth for legal column-to-column transitions on the project board. Pure data — no functions, no I/O. Downstream consumers (#5 `decideLabelDelta`, #7 selection + rework routing) read this table; no consumer wired in this ticket.

## Exports

- `Column` — string-literal union of the seven Status values (`Inbox`, `Backlog`, `In Architecture`, `In Development`, `In Code Review`, `In Documentation`, `Done`).
- `COLUMNS` — `readonly Column[]` runtime mirror in happy-path order. Tests + reachability code need it because TS literal types erase at runtime.
- `Label` — closed union of the labels that some transition's `requires` actually consumes (`ready:po`, `ready:architect`, `ready:developer`, `ready:code-review`, `ready:documentation`, `needs-rework:po`, `needs-rework:architect`, `needs-rework:developer`, `needs-rework:code-review`). `wip:*`, `error:*`, `size:*`, `priority:*`, `security-sensitive` are intentionally absent — they're dispatcher-run lifecycle / metadata, not transition triggers.
- `LabelPattern` — `"ready:*"` | `"needs-rework:*"`. Wildcard prefix patterns used in `Transition.strips`. Same closed-set rule as `Label`.
- `Transition` — `{ from, to, requires, strips }`. ALL labels in `requires` must be present for the transition to fire. `strips` patterns are applied on transition.
- `TRANSITIONS` — 19 rows (6 forward + 13 rework).

## Shape rules encoded in the table

- **`Inbox → Backlog` has empty `requires`** — manual human-triage move with no label trigger. Without it, the reachability invariant fails for every column except Inbox.
- **Forward rows strip nothing.** Matches v1's `runAutoAdvance` semantics. Auto-advance is a column move; the trigger label remains in place until cleanup.
- **`In Documentation → Done` strips `ready:*` + `needs-rework:*`.** Done is terminal; reopened tickets must not carry stale state into a re-run.
- **Rework rows route back to the target agent's column** and strip `ready:*` + `needs-rework:*` so the target re-runs cleanly.
- **Same-column rework rows (`from === to`) are present and deliberate.** `In Architecture → In Architecture` on `needs-rework:architect`, `In Development → In Development` on `needs-rework:developer`, `In Code Review → In Code Review` on `needs-rework:code-review`. The column doesn't change but the labels do — and `decideLabelDelta` is the only place labels mutate. Without these rows, #5 would have to special-case label-only transitions outside the table.
- **No `needs-rework:documentation` rows.** No observed transition routes back into documentation as a rework target. If a future ticket needs it, widen the `Label` union and add the row.

## Test surface

`test/pipeline/transitions.test.ts`, vitest, RED-first. Three load-bearing invariants:

1. **Reachability** — BFS from `Inbox` over `TRANSITIONS` visits every `Column`. One assertion per column with the column name in the message so a regression points at the exact orphan.
2. **`from`/`to` membership in `Column`** — runtime defense against a future `as Column` cast that bypasses the type system.
3. **No dead-letter `strips`** — every `LabelPattern` in any row's `strips` matches at least one label produced by some `requires`. Prefix matching mirrors the `hasNeedsReworkLabel` idiom in `blockers.ts`.

## Out of scope (deferred follow-ups)

- Wiring `decideLabelDelta` (#5), `decideReworkRouting` / `selectDispatches` (#7), or any blocker check into this table. Each consumer is its own ticket.
- A `findTransition(before, after)` validator. That's `decideLabelDelta`'s job (#5); this file is data only.
- `wip:*` / `error:*` in `strips`. They're agent-run lifecycle state, not transition triggers; encoding them here would either violate the dead-letter invariant or force fake `requires` rows.
- `needs-rework:documentation` row(s). No observed need. Add when a transition consumes the label.
