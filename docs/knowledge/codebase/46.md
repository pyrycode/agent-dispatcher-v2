# #46 — `src/pipeline/branch-setup.ts` `decideBranchSetup` + `shouldAutoCommit`

Fifth file under `src/pipeline/` (after #6, #25, #24, #30, #31). Lands two pure predicates the dispatch phase will compose against: branch-naming and the auto-commit safety net.

## Exports

- `BranchSetupState` — narrow input: `{ issueNumber, labels, existingPrHeadRef: string | null }`. `labels` is present for shape-symmetry with `AutoCommitState` so callers can forward one canonical ticket-state object to both predicates; `decideBranchSetup` does NOT read it. PR-existence is the deterministic disambiguator.
- `BranchSetupDecision` — discriminated union: `{ kind: "create", branch }` | `{ kind: "reuse", branch }`. Both arms carry the branch name; `kind` tells the caller whether to spawn or attach.
- `AutoCommitState` — narrow input: `{ commitsAhead, stagedChangesPresent, labels }`. The three-field truth-table input.
- `decideBranchSetup(state)` — `existingPrHeadRef !== null` → `{ kind: "reuse", branch: existingPrHeadRef }`; otherwise `{ kind: "create", branch: "feature/<issueNumber>" }`. Two branches, no helpers.
- `shouldAutoCommit(state)` — `true` iff `commitsAhead === 0` AND `stagedChangesPresent` AND no `needs-rework:*` label. Three guards in order; bottom return is the only `true`.

## Why this file lives in `src/pipeline/` (not `src/worktree/`)

The parent split (#11) listed this under `src/worktree/` for cohesion with the worktree primitives (#43, #44). CLAUDE.md's purity rule wins: these predicates have zero I/O (no `await`, no `gh`/`git`/`fs`), so they sit with their pure-function siblings where the test shape, import conventions, and PR-review expectations are identical. The worktree-side code that *consumes* these (e.g. `createWorktree` in #44) lives in `src/worktree/` separately.

## `shouldAutoCommit` is a belt-and-suspenders backstop

Architect's CLAUDE.md prompt says "you MUST commit your spec." `shouldAutoCommit` is the deterministic check that fires when the agent forgot. The truth table disambiguates four observable post-run states:

| `commitsAhead` | `stagedChangesPresent` | `needs-rework:*` | meaning | result |
|---|---|---|---|---|
| `> 0` | any | any | real commit exists | `false` |
| `=== 0` | `false` | any | silent fail (no work at all) | `false` — `shouldFlagEmptyBranch`'s domain |
| `=== 0` | `true` | no | silent success — agent forgot to commit | **`true`** — safety net fires |
| `=== 0` | `true` | yes | deliberate bail with staged-but-not-committed work | `false` — label is the explicit handoff signal |

Without the `stagedChangesPresent` input the predicate cannot tell silent-success from silent-fail. Both fall through to "no commits", but the former should auto-commit and the latter should escalate to `error:*`.

## Per-agent gating is the caller's concern

`shouldAutoCommit` does NOT inspect agent identity. Per the #6 composition pattern, the caller composes with `shouldProduceCommits(agent, action)` from `blockers.ts` (or a future `shouldAutoCommitForAgent` table). Keeping the predicate generic over state means one truth table to test; per-agent eligibility lives at the dispatch seam.

## Test surface

`test/pipeline/branch-setup.test.ts`, vitest, RED-first. One assertion per row across both truth tables (no `.each` collapsing) so a regression points at the exact failing row. Each `it()` name calls out the row's meaning.

- `decideBranchSetup`: four matrix rows (PR present × `needs-rework:*` present) plus one template-string format guard (`feature/7` for `issueNumber: 7`) — locks the `feature/<n>` literal against a future "render as JSON" simplification.
- `shouldAutoCommit`: six rows (the AC's four bullets expand because "any" on `needs-rework:*` doubles two rows) plus one prefix-vs-substring guard (`"something-needs-rework:po"` does NOT trigger the bail branch). The load-bearing row is `(commitsAhead 0, staged true, no label) → true` — the only `true` in the table.
