# #6 — `src/pipeline/blockers.ts` pure predicates

First file under `src/pipeline/`. Lands three predicates and one internal helper that keep blocker classification and empty-branch routing deterministic — the belt-and-suspenders backstops to stochastic agent prose ("check for blockers", "remember to commit").

## Exports

- `hasOpenBlockers(blockers)` — `true` iff at least one blocker has `state === "OPEN"`. Empty list → `false`. Unknown future states are conservatively treated as not-blocking; a single GitHub schema change cannot deadlock dispatch.
- `parseCommitsAhead(gitRevListOutput)` — parses `git rev-list --count` output to a non-negative integer. Throws on empty input, non-numeric input, partial-numeric input (`"5abc"`), or negative literals. Throwing (vs returning `-1` / `null`) means callers can't silently propagate garbage into `shouldFlagEmptyBranch`.
- `shouldFlagEmptyBranch({ commitsAhead, labels })` — `true` iff `commitsAhead === 0` AND no label has the `needs-rework:` prefix. The label check disambiguates silent agent failure from deliberate bail; the 2026-05-10 relay-#26 incident proved that conflating them mis-routes `error:*` onto a ticket the architect intentionally handed back to PO.
- `shouldProduceCommits(agent, action)` — minimal `(agent, action) → bool` table. Currently returns `true` for every defined `(agent, "run")` pair. Exists as a table (not `() => true`) so that when a second action variant appears, the call site can opt out without touching `shouldFlagEmptyBranch`. Exhaustive `switch` on `AgentName` gives a TS error if a new agent is added without a row here.

`hasNeedsReworkLabel` is internal. Spec rule: promote to `export` only when a second consumer appears (e.g. `src/pipeline/transitions.ts`).

## Test surface

`test/pipeline/blockers.test.ts`, vitest, RED-first. The four-row ambiguity matrix for `shouldFlagEmptyBranch` is one assertion per row so a regression points at the exact failing row in the test output (no `.each` collapsing). Plus a fifth case proving `needs-rework:` is a prefix match, not a substring match.

`parseCommitsAhead` tests include the `"5abc"` regression guard that explicitly rules out `parseInt`-style silent truncation.
