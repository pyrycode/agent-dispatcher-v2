# #30 — `src/pipeline/selection.ts` pure dispatch selector

Lands the `selectDispatches.cap` term of CLAUDE.md's throughput equation. Pure function over a snapshot of board state — given items and a global capacity, return the `(agent, issueNumber)` tuples the dispatcher loop should fire next cycle. No `await`, no `gh` / `git` / `fs` — imports only `./blockers.ts` and `./transitions.ts`.

## Exports

- `Agent` — closed union of agents that consume a column: `"po" | "architect" | "developer" | "code-review" | "documentation"`. **Distinct from `AgentName` in `blockers.ts`** (which is the closed set of commit producers, no `po`). Two narrow types — overlapping by four members today, that overlap is incidental, not structural. Per the #6 narrow-types rule, each pipeline module owns its narrow type for its narrow concern; promote to a shared union only when a third caller actually needs both sets. The drawback (string drift between two type unions) is bounded by both files staying small and pure.
- `AGENT_COLUMN_MAP: Record<Agent, Column>` — five rows, encoded as data. Inbox / Done are absent: Inbox→Backlog is a manual human-triage move (`transitions.ts:78`), Done is terminal. Items in those columns have no consuming agent and are silently skipped. The mapping is **not** derived from `TRANSITIONS` — "label gates this transition" and "agent consumes this column" are distinct concerns; conflating them couples a future label-rename (`ready:po` → `triaged:po`) into selection.
- `SelectionItem` / `SelectionState` / `DispatchTuple` — narrow input/output POJOs defined in-file. `SelectionItem` carries only `column`, `issueNumber`, `labels`, `blockers`. `DispatchTuple` carries only `agent` and `issueNumber` — the dispatcher builds the worktree from the issue number; widening to the full item is future-consumer speculation.
- `selectDispatches(state, maxConcurrent)` — walks `state.items` in caller-supplied order, skips ineligible (wip:* / open-blocker / non-consumed-column), early-`break`s at `result.length >= maxConcurrent`. `maxConcurrent <= 0` short-circuits to `[]` (no-op on negative — matches v1's permissive shape; throwing would force every caller to guard).

## Internal helpers (unexported)

- `COLUMN_TO_AGENT` — reverse map of `AGENT_COLUMN_MAP`, derived at module load. Public table stays the single source of truth; a future change to `AGENT_COLUMN_MAP` cannot drift from the reverse map.
- `isEligible(item)` — composes the wip-gate and blocker-gate. The one place gates compose; future gates add a line here. Stays unexported until a third pipeline gate wants it.
- `hasWipLabel(labels)` — prefix match (`startsWith("wip:")`), not substring. Mirrors `hasNeedsReworkLabel` in `blockers.ts`. Regression-tested: `something-wip:bar` does NOT trigger.

## Per-issue label scoping

Structural property of the loop body, not an explicit branch. Each iteration reads only `item.labels` and `item.blockers`; item B's labels are physically out of scope when deciding item A. Verified by paired tests (one item with `wip:*` / OPEN blocker, sibling item without — sibling is selected, gated item is excluded).

## Test surface

`test/pipeline/selection.test.ts`, vitest, RED-first. One `describe` per AC; one `it` per row. Capacity bounds cover 0, 1, N, beyond-N plus a negative-input no-op. The blocker-gate suite proves integration with `hasOpenBlockers` (one OPEN-and-one-CLOSED case) without re-testing its full matrix — that's `blockers.test.ts`'s job. The column→agent suite has one item per consuming column to pin the five tuples, plus skips for Inbox / Done that prove skipped items don't consume capacity (3 items, `maxConcurrent: 1`, only the Backlog item is returned).

## Out of scope (deferred follow-ups)

- Wiring selectDispatches into `src/loop/` or `src/dispatch/` — neither module exists yet.
- Per-agent capacity caps (e.g. "max 1 architect concurrent"). Today the cap is a single global `maxConcurrent`; per-agent caps would be a new field on `SelectionState`. Add when observed.
- Tiebreak-by-issue-number sort. Caller hands items in priority order (Projects v2 native ordering — total, no ties). Synthetic test inputs set order explicitly. Add a stable secondary sort here if a future caller passes a multi-source aggregate.
- Rate-limit / budget tracking — lives at the loop boundary (PROJECT-MEMORY § (#19)).
- Promoting `isEligible` / `hasWipLabel` / a shared `Agent` union — defer until a second consumer appears.
