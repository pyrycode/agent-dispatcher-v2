# #44 — `src/worktree/create.ts` `createWorktree` + `findWorktreesForBranch` pure helper

Second file under `src/worktree/`. One thin worktree-creation primitive with a pre-flight branch-existence probe, plus a pure parser exported for unit-testing the porcelain walk without the seam. The dispatch layer (future ticket) composes `removeWorktree` (#43) in front of `createWorktree` for collision retry — this primitive makes zero collision-recovery decisions.

## Exports

- `createWorktree(branch: string, repoRoot: string, worktreeDir: string, spawn: Subprocess): Promise<string>` — two awaited spawn calls on the happy path: pre-flight `git -C <repo> rev-parse --verify --quiet refs/heads/<branch>` (exit 0 = exists, exit 1 = absent), then `git worktree add <dir> <branch>` (reuse) or `git worktree add -b <branch> <dir>` (create). Returns `path.resolve(repoRoot, worktreeDir)`.
- `findWorktreesForBranch(porcelain: string, branch: string): WorktreeInfo[]` — pure. Splits on `\r?\n\r?\n`, walks each block looking for `worktree <p>` and `branch refs/heads/<name>` lines, emits one `WorktreeInfo` per block whose stripped branch name equals the input. Multiple matches preserved in encounter order.
- `WorktreeInfo` — `{ readonly path: string; readonly branch: string }`. Two fields per the #6 narrow-types rule; widen at the moment a consumer needs more.

`Subprocess` / `SubprocessResult` are imported from `./cleanup.ts`, NOT redefined — second importer per the one-shared / second-imports / third-promotes ladder. Promotion to a shared module is the third caller's concern.

## Invariants encoded

- **Pre-flight `rev-parse` over try-and-fall-back.** Two awaited spawns on the happy path, both with deterministic argv. The alternative — try `-b` first, recover on the "branch already exists" stderr — couples the module to git's exact error-message wording and is brittle across versions. The extra round-trip is one process spawn (same order of magnitude as `worktree add` itself); robustness wins. Tests #1/#2 pin both the `-b` and bare argv shapes deeply, so a future "always use `-B`" simplification breaks them immediately.
- **`rev-parse` exit ∉ {0, 1} surfaces verbatim.** Only those two codes are documented signals (present / absent); anything else is abnormal git state and propagates through the same `throw new Error(stderr.trim() || fallback)` shape as the `worktree add` failure path. No silent absorption of unexpected probes.
- **`git -C <repoRoot>`, NOT a `cwd` parameter on `Subprocess`.** Widening the seam to `(argv, opts?: { cwd? })` would cascade into `cleanup.ts`'s tests and every future caller for zero benefit `git -C` doesn't already provide. Per the #6 narrow-types rule, the seam stays minimal; the redirection is git's documented idiom.
- **Caller passes the short branch name; parser strips `refs/heads/`.** Same posture as `findCollidingWorktree` (caller passes the path it gave to `git worktree add`, parser matches what porcelain echoes). Porcelain prepends `refs/heads/` on `branch` lines; the parser slices it off before the equality check. Branches under `refs/tags/` or other namespaces match nothing — silently skipped, not an error.
- **Multiple matches return all, in encounter order.** `git worktree add --force` makes a branch reachable at multiple paths; the array shape captures that. Test #5 pins both that all matches return AND the order is preserved (so a future `Set`-based dedup or `.sort()` would break it).
- **Blocks without a `branch refs/heads/...` line are silently skipped.** Bare worktrees, detached HEADs, tag-ref worktrees, malformed lines — all dropped without throwing. AC's "malformed lines silently skipped." Test #7 mixes a normal block with a detached block, a `refs/tags/v1` block, and stray garbage lines; assertion is exactly the one valid `feature/44` entry.
- **Errors propagate stderr verbatim** (`.trim()`-ed only to dodge trailing newlines). Mirrors `cleanup.ts`'s "no catch around transport" posture. The "branch already checked out elsewhere" / "directory exists" failure modes route through the same `worktree add` non-zero exit branch — no special-casing inside this primitive. Test #3 pins the canary substring.
- **Return value is `path.resolve(repoRoot, worktreeDir)`** — absolute path. Absolute `worktreeDir` is a noop; relative is joined against `repoRoot` (the same base `git -C` uses, so the returned path matches what `git worktree list --porcelain` will echo). No `realpath` / symlink resolution — matches git's posture, keeps caller paths consistent with porcelain reports.
- **No filesystem reads.** Unlike `removeWorktree`'s `pathExists` fast-path (which is removal-specific because absent-on-disk is a noop), there's no analogue here: "the worktree to be created already exists on disk" is the collision case the dispatch layer handles, not silently absorbed. Tests use arbitrary string fixtures (`/tmp/repo`, `/tmp/wt-44`) without `mkdtempSync`.

## Design choices

- **Free function, not a class.** Same posture as `cleanup.ts` — no state to bind, no precondition to protect. A `WorktreeCreateClient.create(spawn)` factory would buy zero semantic gain.
- **`Subprocess` imported, not redeclared.** Sibling-module imports inside `src/worktree/` are explicitly fine (CLAUDE.md "no barrels" forbids `src/index.ts` re-exports, not direct sibling imports). Same one-canonical-source posture as `GraphQLTransport` (#37 imports from #19) and `RestTransport` (#36 imports from #35).
- **Pure parser exported.** `findWorktreesForBranch` lives in the same file as `createWorktree` rather than a sibling — the seam-free unit tests sit in their own `describe` block, and the file lands at 90 lines (under the 200-line hardcap). Splitting would speculate on a hypothetical reuse.
- **No paragraph-block tokenizer shared with `findCollidingWorktree`.** Both parsers walk the same porcelain grammar but return different shapes (exact-or-null path vs `WorktreeInfo[]`) and match on different fields (path vs branch). A `parseBlocks(porcelain) → Block[]` extraction would be strictly nicer; explicit "while I'm here" refactor and out of scope for #44 per CLAUDE.md. File a follow-up if a third porcelain consumer lands.
- **Four positional args, no opts object.** `(branch, repoRoot, worktreeDir, spawn)` is the minimum viable surface. No `{ force?, detach?, ... }` extensibility object — narrow types per #6, add parameters when callers need them.
- **No validation that `repoRoot` exists / is a git repo.** `git -C <bad-path>` already produces a clear error; wrapping it would add a defensive check for a failure mode no caller has demonstrated (CLAUDE.md "Don't write a defense for a failure mode that hasn't been observed").

## Test surface

`test/worktree/create.test.ts`, vitest, RED-first per CLAUDE.md. 7 `it` blocks across two `describe`s. The `makeSpawn` / `ok` / `fail` / `argvEq` helpers are copied verbatim from `test/worktree/cleanup.test.ts:1-46` — second user; per architect's spec, third worktree test file should drive extraction to a shared util.

The load-bearing rows:

- **`happy path — new branch, -b form runs`.** Routes pre-flight to `fail("")` (exit 1, the documented absent-branch signal); routes `worktree add -b feature/44 <dir>` to `ok()`. Pin: `t.calls.length === 2`, `t.calls[1]` deep-equals the `-b` argv, return value is `path.resolve(REPO, WORKTREE)`. The `fail("")` route resolving to exit 1 (not throwing) is the contract pin against any future "treat exit 1 as error" simplification.
- **`branch exists — bare form runs (no -b)`.** Routes pre-flight to `ok()` (exit 0); routes `worktree add <dir> feature/44` to `ok()`. Pin: `t.calls[1]` deep-equals the bare argv. The bare-vs-`-b` discrimination is the load-bearing test surface — a future "always use `-B`" simplification fails this assertion.
- **`worktree add fails — surfaces stderr verbatim`.** Routes `worktree add` to `fail("fatal: '/tmp/wt-44' already exists")`; asserts `caught.message` contains `"already exists"`. Pinning the substring (not the full message) tolerates the `.trim()` step. Same shape as cleanup's "list fails — surfaces stderr verbatim."
- **`findWorktreesForBranch` four pure-parser tests.** Single match, multiple matches (preserves encounter order), no matches (returns `[]`), malformed/non-branch blocks silently skipped (mixed-block fixture asserts exactly one valid entry).

No real `git` invocations; no `child_process` import in either source or test (per AC #4 — verified by inspection).
