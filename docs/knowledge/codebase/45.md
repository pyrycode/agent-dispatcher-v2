# #45 — `src/worktree/codegraph-link.ts` `decideCodegraphSymlink` (pure) + applier

Second file under `src/worktree/`. Pure decision (`decideCodegraphSymlink`) plus an I/O applier (`applyCodegraphSymlinkActions`) over a narrow `SymlinkFs` seam, co-located in one file. Lets the dispatcher symlink the canonical `<targetRepo>/.codegraph` index into a fresh worktree so dispatched agents running with the codegraph MCP server can adopt it. The agent-side `allowedTools` grant is necessary but not sufficient — without this seam being load-bearing in code, the next refactor that cleans up the symlink call would silently regress codegraph adoption (the failure mode is invisible from the dispatcher's side).

## Exports

- `decideCodegraphSymlink(input): SymlinkAction[]` — pure. Exhaustive `switch` over `state.kind`; returns a 1-element array per the four-row table below.
- `applyCodegraphSymlinkActions(actions, fs): Promise<void>` — applier. Walks the list; `noop` skips, `repair` is `unlink` then `symlink`, `create` is `symlink` only.
- `CodegraphLinkState` — closed union of `"absent" | "present-correct" | "present-wrong-target" | "target-missing"` (caller pre-computes by probing fs).
- `SymlinkAction` — flat `{ kind: "create" | "repair" | "noop"; from; to; reason? }`.
- `DecideCodegraphSymlinkInput` — `{ worktreeRoot; targetCodegraphPath; state }`.
- `SymlinkFs` — DI seam: `{ symlink(target, path), unlink(path) }` — method names match `node:fs/promises` so production wiring is a free pass-through.
- `NOOP_TARGET_MISSING = "target-missing"`, `NOOP_ALREADY_CORRECT = "already-correct"` — named noop reasons callers branch on without re-deriving the state.

## The four-row table

| `state.kind` | Output |
|---|---|
| `absent` | `[{ kind: "create", from, to }]` |
| `present-correct` | `[{ kind: "noop", from, to, reason: NOOP_ALREADY_CORRECT }]` |
| `present-wrong-target` | `[{ kind: "repair", from, to }]` |
| `target-missing` | `[{ kind: "noop", from, to, reason: NOOP_TARGET_MISSING }]` |

`from` is the link's target (the canonical `.codegraph`); `to` is the link's path (`<worktreeRoot>/.codegraph`). Order matches POSIX `symlink(2)` and `node:fs/promises.symlink(target, path)` — the applier passes `(action.from, action.to)` directly with no swap.

## Invariants encoded

- **Pure + applier collapsed into one file under `src/worktree/`.** CLAUDE.md's canonical home for the pure function is `src/pipeline/`; the AC explicitly green-lit collapsing if the function is small enough that the split adds more friction than it removes. Both halves are tiny (~15 + ~10 lines), the pure function has exactly one consumer in the same directory, and the precedent is `findCollidingWorktree` in `cleanup.ts` (#43) — same posture, same justification. If a non-worktree consumer ever appears, promote `decideCodegraphSymlink` to `src/pipeline/codegraph-link.ts` then.
- **Exhaustive `switch` with no `default`.** A future fifth state is a TS compile error rather than a silent missing row. Mirrors `shouldProduceCommits` in `pipeline/blockers.ts`.
- **`target-missing` is a non-error `noop`, not a throw.** Not every target repo has a codegraph index; the dispatcher must not crash when it's absent. Surfacing as a typed noop with a named reason lets the caller log-and-continue without re-deriving the branch. Same shape rule as `mergePr`'s `{ merged: false, reason }` (#41) — when a wrapper's failure has a structured downstream consequence (here: log "no index" warning) AND the failure mode is detectable from state, surface it as a typed return.
- **`present-wrong-target` carries `currentTarget` in the input but NOT in the output.** The applier `unlink`s the path, not the target — it doesn't need `currentTarget`. Pinned by `expect(actions[0]).not.toHaveProperty("currentTarget")`. Per the #6 narrow-types rule, don't widen the action shape with fields the consumer doesn't read.
- **`repair` = `unlink` then `symlink`, in that order.** Symlinking before unlinking would `EEXIST` on a real fs; the in-memory fake won't catch that, so the applier test pins the sequence explicitly. The window between `unlink` succeeding and `symlink` failing is the cost of repair-as-unlink-then-symlink; the next dispatch's probe sees `absent` and re-creates. Atomic-rename hardening is deferred until observed.
- **`POSIX path.join`, not platform-conditional `node:path`.** Dispatcher worktrees are Unix-only; POSIX semantics (`/` separator) are deterministic. `import { posix as path } from "node:path"` is the only Node import in the production module — pure string function, no I/O.
- **Errors propagate verbatim.** No try/catch in the applier; `SymlinkFs` rejection surfaces raw. Same posture as `cleanup.ts` (#43) and `labels.ts` (#36). A `repair` whose `unlink` succeeds but whose `symlink` fails leaves the worktree without a `.codegraph` entry; the next dispatch cycle's probe sees `absent` and re-creates.
- **Single-call serial — no `Promise.all`.** The applier walks the action list with sequential `await`s. A `repair`'s `symlink` must only run after its `unlink` succeeded. The dispatcher's loop is the concurrency owner; this module's calls serialize within one dispatch's worktree-setup phase.
- **State probe is out of scope.** This module takes a pre-computed `CodegraphLinkState`. Computing it (`fs.lstat` / `fs.readlink` / `fs.access`) lives at the dispatch-layer integration ticket where the probe has a real callsite to constrain its signature.

## Design choices

- **Free function over class.** No state to bind, mirroring `cleanup.ts` (#43); the `src/github/` clients bind transport + (owner, repo) once because they have state, this primitive doesn't.
- **`SymlinkFs` is a NEW narrow DI seam, NOT a reuse.** Each I/O boundary owns its narrow type for its narrow concern (`RestTransport` HTTP-shaped, `GraphQLTransport` query-shaped, `Subprocess` argv-shaped, `SymlinkFs` fs-shaped). A callable shape (`(op, args) => Promise<void>`) loses TypeScript's parameter typing per op. The two-method object matches `node:fs/promises`'s actual surface — production wiring is one line: `applyCodegraphSymlinkActions(actions, fs.promises)`. Co-located in `codegraph-link.ts` until a second caller appears; promote to `src/runtime/fs.ts` (or similar) on the third — same one-shared / second-imports / third-promotes ladder as `Subprocess`.
- **Both noop reasons are named constants.** AC's "(or equivalent named constant)" phrasing was for `target-missing` specifically; applying it to `present-correct` too is the consistent shape and lets callers differentiate "no index in target repo, fine" from "already linked, nothing to do" without substring-matching string literals.
- **Flat `SymlinkAction`, not a discriminated union.** The AC's example shape is flat; the applier's `kind` check doesn't benefit from narrowing (it never reads `reason`). Flat keeps the type surface minimal.
- **Array return, not a single value.** AC says "list of actions"; cost of `[action]` over `action` is one `[0]` index at the callsite; widening later would break the contract.

## Test surface

`test/worktree/codegraph-link.test.ts`, vitest, RED-first per CLAUDE.md. Two `describe` blocks (4 + 5 `it`s) plus a `makeFs(routes)` recording fake mirroring `makeSpawn` from `test/worktree/cleanup.test.ts` retyped to `SymlinkFs`. The `calls` log is the verification mechanism for the AC's "no real symlinks created on the test host's filesystem" pin.

The load-bearing rows:

- **`noop action → zero fs calls`.** No routes registered, so any spawn would hit `No route matched: ...` and fail. Pin: `t.calls.length === 0`. A future "always log/probe even on noop" simplification would still satisfy "no throw" but fails this count.
- **`repair → unlink then symlink, in that order`.** `t.calls[0]` is `["unlink", TO]`, `t.calls[1]` is `["symlink", FROM, TO]`. Order is load-bearing — symlinking before unlinking would `EEXIST` on a real fs.
- **Pure-decision tests pin the named constants** (`NOOP_ALREADY_CORRECT` / `NOOP_TARGET_MISSING`), not the string literals. A future rename of the constant would break this assertion if it didn't update the test in lockstep — the regression guard against constant drift.
- **`symlink rejection propagates verbatim`.** Canary "`CANARY: EACCES`" surfaces in `caught.message`. Mirrors `cleanup.test.ts`'s "list fails — surfaces stderr verbatim" and `labels.test.ts`'s "transport-failure THROWS".

No `node:fs` / `node:fs/promises` import in either source or test (verified by inspection). No `process.env` reads.
