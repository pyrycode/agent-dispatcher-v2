# #19 — `src/github/project-client.ts` org-aware Projects v2 client

First file under `src/github/`. The single I/O initialization surface every other `src/github/*` module (and the loop's state-fetch) will share. Lands project resolution + Status field caching + items-in-board-order; sibling tickets (#20 issues, #21 labels/PR) consume this client via DI.

## Exports

- `GitHubProjectClient.initialize(opts, transport)` — async factory; the only entry point. Resolves project ID + Status field ID + Status option IDs up front, returns a fully-initialized instance. The constructor is private — every method can rely on cached IDs without `if (!projectId) throw "Not initialized"` guards.
- `client.listItemsInBoardOrder()` — paginates `node(...).items(orderBy: { field: POSITION, direction: ASC })`, returns `readonly ProjectItem[]` in the order GraphQL gave them. Never derives ordering from `issueNumber`.
- `OwnerType` — `"user" | "organization"`.
- `InitializeOpts` — `{ owner, project, ownerType }`.
- `ProjectItem` — narrow shape: `id`, `issueNumber`, `title`, `status`, `labels`, `url`. No `body` / `blockedBy` / etc. — sibling tickets widen when they need them.
- `GraphQLTransport` — `(query, variables) => Promise<unknown>`. Mirrors `@octokit/graphql`'s callable shape so production wiring is one line; tests hand-roll a fake.

## Invariants encoded

- **Org-aware dispatch is explicit.** `ownerType === "organization"` interpolates `organization(login:)` into the init query; `"user"` interpolates `user(login:)`. NO try/catch fallback. A mismatched `ownerType` propagates the GraphQL error verbatim — masking it as "wrong owner type" would convert every auth/rate-limit/transient failure into bad advice. Test #3 locks this with a canary substring assertion (`Could not resolve to a User`) plus `transport.calls.length === 1` (no fallback retry).
- **Native ordering, never derived.** Items query uses `orderBy: { field: POSITION, direction: ASC }`. Test #4 feeds in scrambled-issue-number nodes and asserts the array is returned in transport order, with an explicit `.not.toEqual([10, 20, 30, 50])` regression guard against any future "let's sort for stability" simplification.
- **Pagination cap = 50 pages (5000 items).** v1 #203 was the precedent for paginating at all; the cap is the regression guard against runaway loops (echoed `endCursor`, broken `hasNextPage`). Throws with a message that names the failure mode. Test #6 locks this.

## Design choices

- **Static factory + private constructor.** Mirrors `parseConfig` / `loadConfig` in #3 — the wrapper makes a precondition unfakable (here: "project IDs are resolved before any method call"). v1's `new ... + .initialize()` pattern let callers forget; the private constructor ensures they can't.
- **Transport is a callable, not a class with methods.** `(query, variables) => Promise<unknown>` matches `@octokit/graphql.defaults({...})`'s exported shape. Tests hand-roll a routing-table function — no mock library, no `as any`, no inheritance. The `calls` log is the verification mechanism for "transport receives the right query".
- **No `@octokit/graphql` dep added.** This module is dep-free — only Node built-ins. The launcher (later ticket) decides on the production transport. `package.json` is unchanged in this ticket.
- **`status` defaults to `"no-status"` sentinel** when `fieldValueByName` is null. Keeps `ProjectItem.status: string` (not `string | null`), which keeps consumer types simpler. Matches v1.
- **GraphQL queries are minified single-line strings.** Multi-line indented queries pushed the file past the 200-line hardcap; the queries are opaque to the rest of the system, so collapsing whitespace is the obvious fix.

## Test surface

`test/github/project-client.test.ts`, vitest, RED-first. 10 cases across two `describe` blocks (`initialize`, `listItemsInBoardOrder`). Each test builds its own routing table inline so a regression points at the exact failing scenario; no shared fixtures across tests.

The two load-bearing rows:

- #3 — mismatched `ownerType` propagates verbatim + no fallback retry. Locks the no-fallback contract against any future "try org, catch, retry as user" wrapper.
- #4 — POSITION ordering, not derived from `issueNumber`. Locks the native-ordering contract against any future "sort for stable test ordering" simplification.

## Out of scope (deferred follow-ups)

- Wiring this client into the launcher (`src/dispatch-bin.ts`) or any loop. Consumers land in their own tickets.
- `getIssue`, label mutations, PR helpers, `blockedBy` queries, status mutations — sibling tickets (#20, #21).
- Per-cycle items cache. v1 carries one for valid reasons; v2's caching layer belongs at the loop boundary, not in this primitive.
- Rate-limit tracking + per-cycle budget logging. Defer until budget pressure is observed.
- Retry / backoff. The injected transport handles its own resilience policy; this module is concerned with project semantics, not network resilience.
- Adding `@octokit/graphql` to `package.json`. Happens when the launcher needs the production transport.
- Promoting the test routing-table helper to `test/github/_helpers/transport.ts`. Defer until a second consumer (sibling test file) appears — same rule as `hasNeedsReworkLabel` in #6.
