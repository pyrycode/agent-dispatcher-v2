# #42 — `src/pipeline/find-ready-pr.ts` pure `findReadyPrNumber` predicate

A single pure predicate that classifies a list of PR candidates and picks the lowest-numbered "ready" one (or `null` if none qualify). "Ready" means: not a draft AND no label matching the `error:*` global-block prefix. Lives in `src/pipeline/` per CLAUDE.md ("Pure functions in `src/pipeline/`, I/O at the edges"); the PR shapes come in as POJOs from a future `src/github/` list-query, the lowest qualifying number goes out.

## Exports

- `findReadyPrNumber(prs: readonly ReadyPrCandidate[]): number | null` — single-pass min-tracking loop. Drafts and `error:*`-labeled PRs are skipped; lowest surviving `number` wins. Empty input → `null`.
- `ReadyPrCandidate` — `extends PrInfo` with `readonly isDraft: boolean` and `readonly labels: readonly string[]`. Type-only `import type { PrInfo } from "../github/pr.ts"` is the only import; AC #1's enumeration of forbidden import directories (`src/github/`, `src/claude/`, `src/worktree/`, `src/salvage/`, `src/index.ts`) is satisfied because `import type` is erased at compile time and AC #1 explicitly names `PrInfo` as the allowed crossing.

`hasErrorLabel` and `ERROR_LABEL_PREFIX` are file-local. Helpers stay unexported until a second consumer appears (#6 narrow-types rule).

## Invariants encoded

- **Drafts are not ready, even with the right labels.** Predicate-completeness fix from 2026-05-03: a draft PR carrying `ready:code-review` was selected for auto-merge because the prior code keyed on labels alone. The fix is the second filter row, not a one-off carve-out — every PR-shape variant the predicate distinguishes has a row in the test matrix. Row B (`isDraft=true, labels=[]` → null) is the canary.
- **`error:*` global-block labels veto.** Any label starting with `error:` filters the PR out. The closed prefix-match is the same shape as `hasWipLabel` (#30) and `hasNeedsReworkLabel` (#6) — substring matches are bug magnets. Regression row pins `something-error:foo` is NOT filtered; baseline row pins `ready:code-review` is NOT filtered.
- **Bare `error:` (empty suffix) IS filtered.** Closed semantics: prefix-match is permissive by design. Today no real label collides; if a future `error:*`-prefixed label is NOT a global block, the assumption breaks and an exclusion list lands at that point. Test row pins the current behavior.
- **Lowest PR number wins, deterministically.** When multiple PRs survive both filters, single-pass `< lowest` tracking picks the lowest. GitHub PR numbers are monotonically increasing, so "lowest" means "oldest open ready PR" — matches v1's "older first" tiebreak. Strict `<` (not `<=`) means duplicate numbers (impossible in production) would resolve first-seen-wins; not load-bearing.
- **Input order does NOT affect output.** Three explicit test rows — `[#10,#3,#7]`, `[#7,#10,#3]`, `[#3,#7,#10]` — all yield `3`. A regression to "first-pass" or "last-pass" surfaces at the offending row, not as a single composite assertion.
- **No defensive widening.** `pr.labels` is read directly, no `?? []`. TypeScript types are the contract; if a caller passes `undefined`, that's a caller bug at the I/O boundary. Same posture as `blockers.ts` and `selection.ts`.
- **No runtime validation against `PrInfo`.** Predicate reads only `number`, `isDraft`, `labels`; `nodeId` and `url` are caller-supplied passthrough that this module never inspects. Per CLAUDE.md "Don't write a defense for a failure mode that hasn't been observed."

## Design choices

- **`ReadyPrCandidate extends PrInfo`, not a fully local input type.** Three options were considered: (1) a fully local `{ number, isDraft, labels }` shape (no `pr.ts` import at all — AC's literal reading allows it, but disconnects the input shape from the future list-PRs query's output); (2) widen `PrInfo` itself in `pr.ts` (cross-ticket change to a landed module, drags out of scope, and `createPr`'s response path doesn't carry draft state); (3) `extends PrInfo` here (additive, type-only, anchors via TypeScript's structural subtyping). Option 3 is the cheap, correct seam — the future list query returns `ReadyPrCandidate[]` (or a wider superset) and this predicate consumes it with no further work.
- **Type-only import, not a value import.** `import type { PrInfo }` is erased at compile time so no runtime edge crosses the I/O boundary. AC #1 explicitly bans function imports from `src/github/`; the type crossing is the one allowed seam.
- **Single-pass min-tracking loop, not `[...prs].sort()[0]`.** Same code-shape as the existing pipeline predicates (`selectDispatches`'s early-`break` / `result.push` shape). Sorting a typical input (one or two candidates per cycle) is a no-op overhead and would speculate on a "stable sort guaranteed" semantic the pipeline doesn't otherwise rely on.
- **`mkPr` test helper, not inline literals.** Each row needs `nodeId` and `url` stub strings to satisfy the `extends PrInfo` shape; inlining 5 fields per row would crowd out the predicate's actual concerns (`number`, `isDraft`, `labels`). The selection-test precedent (`mkState`) is one-field; this one is three. Suggested by the spec when 4+ fields per row become repetitive.
- **Predicate-completeness audit comment is the test-file header, not the source-file header.** The 2×2 grid IS the assertion matrix; its natural home is next to its rows. Source file header references the audit by file path so a future contributor reading the source knows where the matrix lives.

## Test surface

`test/pipeline/find-ready-pr.test.ts`, vitest, RED-first per CLAUDE.md. 18 `it` blocks across 5 `describe`s plus a `mkPr` helper at the top. Row tags (`// audit: row A` … `// audit: row D`) sit inside the four predicate-completeness `it` bodies so a regression points at the exact failing variant.

The load-bearing rows:

- **Row B (`isDraft=true, labels=[]` → null).** The 2026-05-03 predicate-completeness fix. Prior code keyed on labels alone; this row pins that drafts are filtered even without negative label evidence.
- **`bare error:` row → null.** Pins the closed prefix semantics. If a future ticket needs to allow a bare `error:` label through, this row breaks first.
- **`something-error:foo` row → 1.** Prefix-match regression guard, mirrors `something-wip:bar` in `selection.test.ts:117`.
- **Three input-order independence rows.** One `it` per ordering, not a single composite — a regression to "first-pass" or "last-pass" must surface at the offending row.
- **Mixed row (ready #7, draft #1, ready #3, error-labeled #2 → 3).** The composition canary. A regression that picks `1` (no draft filter) or `2` (no error filter) breaks here.
