# #37 — `src/github/blocked-by.ts` GraphQL `addBlockedBy` mutation wrapper

Third file under `src/github/`. The deterministic primitive the architect's split flow uses to mark a child sub-issue as blocked by an earlier child via the native sub-issue relationship — pairing the architect's "set the dependency" prose with a deterministic GraphQL primitive (CLAUDE.md "Belt-and-suspenders"). The dispatcher's `hasOpenBlockers` predicate (#6, merged) reads the same native relationship; consumers of this primitive land in their own tickets.

## Exports

- `addBlockedBy(blockedNodeId, blockerNodeId, transport)` — single async free function. Returns `Promise<void>`. The whole module body is one `await transport(query, variables)` call.

`GraphQLTransport` is re-imported from `project-client.ts` (#19) — single source of truth for the DI seam. Not redeclared here; not re-exported.

## Invariants encoded

- **Role mapping pinned by the test.** The GraphQL mutation's `issueId` is the BLOCKED issue; `blockingIssueId` is the BLOCKER. The wrapper's argument names spell the roles (`blockedNodeId` / `blockerNodeId`) so the call site reads unambiguously. Test #1 deep-equals the transport variables — `{ issueId: blockedNodeId, blockingIssueId: blockerNodeId }` — to lock the mapping. A future "swap these for symmetry" simplification would set the dependency the wrong way around and fail this assertion immediately.
- **No fallback retry.** Test #2 asserts `t.calls.length === 1` after a thrown route. A future try/retry shim (e.g. retry on `RATE_LIMITED`) would either update this assertion (visible in the diff) or break it (caught in CI). Either outcome surfaces the deviation.
- **Error message propagates verbatim.** Test #2 uses an exact-substring match (`Could not resolve to a node`) — the contract is "the underlying error reaches the caller intact." If a future PR wraps the call in `try { ... } catch (cause) { throw new Error("addBlockedBy failed: " + cause.message); }`, the canary still passes (substring preserved) but the `calls.length === 1` assertion catches any retry. Together they lock the no-fallback, no-rewriting contract.
- **Takes node IDs, not issue numbers.** Architectural decision: the GraphQL mutation requires node IDs natively; a hidden number→nodeId resolution inside this primitive would add a round-trip the call site can't see. Callers compose with `src/github/issues.ts` (#35) before calling here. Same "narrow types at the boundary" posture as #6 / #19.

## Design choices

- **Free function, not a class.** `project-client.ts` is a class because it caches resolved IDs across method calls; `issues.ts` is a class because it binds `(owner, repo, transport)` once. This module has no state to cache and no precondition to protect — a `BlockedByClient.create(transport)` factory just so callers can do `client.addBlockedBy(a, b)` instead of `addBlockedBy(a, b, transport)` is API surface for no semantic gain. If a future ticket binds `(transport)` once across many call sites, a thin wrapper is a non-breaking addition.
- **Imports `GraphQLTransport` from `project-client.ts`.** Single source of truth for the DI seam — when the launcher decides on the production transport (`@octokit/graphql.defaults({...})` or a `gh api graphql` shell-out), it instantiates one and threads it through every consumer. Redeclaring would create two structurally identical types that drift the moment a future ticket widens the seam (e.g. to add an `AbortSignal` parameter). CLAUDE.md "no barrels inside `src/`" forbids `src/index.ts` re-exports; it does not forbid sibling-module imports.
- **Mutation as a top-level minified `const`.** Matches the `INIT_QUERY` / `ITEMS_QUERY` shape in `project-client.ts:47-50` — groups all GraphQL strings at the top of the file, dodges the 200-line hardcap consistently across the directory.
- **`Promise<void>` return.** The mutation's `issue { number }` selection set is the GraphQL API's sanity round-trip (`addBlockedBy(...) { ... }` requires a non-empty selection); the response is intentionally discarded. The absence of a thrown error IS the success signal. If a future caller wants the number for logging, the return type widens non-breakingly.
- **No try/catch, no input validation.** Empty-string node IDs are a caller bug; the GraphQL transport returns the canonical error (`Could not resolve to a node with the global id of '...'`) which is more useful than a wrapper-thrown `Error("blockedNodeId is empty")`. Per CLAUDE.md "Don't write a defense for a failure mode that hasn't been observed."

## Test surface

`test/github/blocked-by.test.ts`, vitest, RED-first per CLAUDE.md. Two `it` blocks under one `describe("addBlockedBy")` plus an inline `makeTransport(routes)` helper that mirrors `test/github/project-client.test.ts:8-32`.

The two load-bearing rows:

- **Test #1 — happy path; variables deep-equal `{ issueId, blockingIssueId }`.** Locks the role mapping. Also asserts `t.calls.length === 1` (no retry) and that the query string includes `addBlockedBy(input:`.
- **Test #2 — invalid node ID; canary substring + `t.calls.length === 1`.** Locks both the verbatim-error contract and the no-fallback contract.

The hand-rolled `makeTransport(routes)` helper is duplicated inline here (second consumer); per #19 § "Open question 5", promote to `test/github/_helpers/transport.ts` only when a *third* GraphQL consumer appears.
